# 工程4に向けた取り込み・正規化設計

**設計のみ。取り込み処理、正規化済みイベント、シミュレーションは未実装。** 対象・採用条件は[調査報告](README.md)、固定出典とハッシュは[manifest.json](manifest.json)に従う。

## 1. 原本と管理単位

データセットID案は `moss-evans-2022-flower-visits-v1`。正本は大学保管v1、ファイルID `34178859` のCRLF版とする。GitHubの固定コミットのLF版も同じ記録内容として照合済みだが、**バイト単位の別スナップショット**として区別する。

工程4で置く構成案：

| 配置案 | 内容 |
| --- | --- |
| `data/raw/<dataset-id>/Raw_InteractionData_BothYears.csv` | 取得した原バイトを保持。改行変換を防ぎSHA-256を検証 |
| `data/raw/<dataset-id>/source.json` | DOI・版・ファイルID・取得日時UTC・取得URL・サイズ・ハッシュ・利用条件の証拠 |
| `data/processed/<dataset-id>/events.json` | 原行と対応付けたイベント。重複行も別イベント |
| `data/processed/<dataset-id>/taxa.json` | 植物・昆虫を分けた原ラベル辞書。確定種と断定しない |
| `data/processed/<dataset-id>/quality.json` | 欠測・重複同値パターン・未解決ラベル等の検査結果 |
| `data/processed/<dataset-id>/provenance.json` | schema/transform/taxonomyの版、変換コードのコミット、入出力ハッシュ |

まだこれらのディレクトリ・データを作成しない。原本をGit管理する工程4では、対象パスに改行変換を適用しない `.gitattributes` 等の設定も検討・検証する。正本CRLFをGitの自動処理でLFへ変えた後、元ハッシュのまま扱うことを防ぐ。

## 2. 変換ルール案 `ccpp-verbatim-v1`

| 対象 | ルール |
| --- | --- |
| 入力 | 許可済みの版・ハッシュを必須にし、取り込み前に原バイトのSHA-256を比較 |
| CSV | UTF-8、カンマ区切り、7列、ヘッダー順を固定。CRLF/LFを正しく解釈するCSVパーサーを使い、文字列splitで代用しない |
| 行番号 | ヘッダーを除く1始まりのCSV論理レコード番号。物理行番号と区別して保存 |
| Year | 2014/2015の整数に厳密変換。補助資料の1/2をこの列へ混入させない |
| Plot | 元の1〜24を識別子として保持。区画年IDはYearとPlotの組 |
| Round | 2014は1,3,4,5,7,8,9、2015は1〜7の元ラベルを保持。全体の最大値9を根拠に各年9回としない |
| Plant / Specimen_ID | 元文字列を完全保持。表示時のアンダースコア置換は表示用だけ。原値を上書きしない |
| 種の識別子 | `plant:<raw-label>` / `visitor:<raw-label>` 等、両側を区別した原ラベル識別子。学術的な種IDと呼ばない |
| Basic_Type / Treatment | 原値を列挙値として検証。独自の生態学的機能群へ推測変換しない |
| 重複 | 全行保持。7列同値をエラーとして落とさず、回数と原行番号で追跡可能にする |
| 欠測 | 予期しない空欄・欠測表記・不正型は隔離/失敗として明示。0や任意の種で補完しない |
| 不明な実施情報 | 日付、時刻、実績努力量、ブロックはnull/未確認。方法の20分を各記録の測定値として付けない |
| 並び順 | 原CSVの行順を保持。別途ソートする派生ビューはキー・照合規則を記録。原順を観測時系列と呼ばない |
| 数値形式 | JSONでは年等を数値、欠測をnullとして扱う。NaN、空文字の数値化、暗黙の型変換を禁止 |

## 3. イベントのフィールド設計案

| フィールド | 型案 | 由来・意味 |
| --- | --- | --- |
| dataset_id | string | 版を固定したデータセットID |
| source_sha256 | string | 実際に使用した原バイトのハッシュ |
| source_record_number | integer | ヘッダーを除く原順1〜3,882 |
| record_id | string | `sha256:<source_sha256>:record:<source_record_number>`。原同値行も区別する |
| year | integer | Year |
| plot_id | string | Plotの元識別子 |
| round_label | string | Roundの元識別子。日付ではない |
| plot_year_id | string | 年と区画から衝突しない規則で生成 |
| observation_group_id | string | 年・区画・元Roundの組。実施済みセッションであることの追加証明とはしない |
| treatment | string | Treatment |
| plant_label_raw / visitor_label_raw | string | Plant / Specimen_ID |
| plant_label_id / visitor_label_id | string | 植物・昆虫を分けた原ラベルキー |
| basic_type_raw | string | Basic_Type |
| observed_at / actual_effort_minutes / block_id | null | 対象CSVには情報なし。別途の検証済み資料なしに埋めない |

同一内容でもCRLF/LFの原本ハッシュが異なればrecord_idは異なる。2版の対応は、この監査で確認した「同じ論理レコード番号・全値・順序」の関係を来歴に記録する。改行変換後のハッシュで原本IDを後付け変更しない。

## 4. 観測単位と行のない組合せ

イベントは正の訪花記録の行。年×区画×Roundの台帳を作る場合、まず記録がある321組と、記録がない15組を区別する。後者の状態は `no_record_effort_unknown` とし、`surveyed_zero` にしない。日付台帳や実施記録が得られた場合だけ、別の根拠付き更新として状態を変える。

ペアの集計で0を作る場合も、0の意味は「選択した元記録中にこのペアの行なし」に限定する。「自然界に関係なし」や「観測済みで不在」の符号にしない。分類集合・分母・抽出単位は工程5で定義する。

## 5. 分類名の対応表を別管理する

原ラベル版を最初の処理仕様にする。異名統合・綴り修正を行う場合は、別版の対応表に次を記録する。

`raw_label`、対象側（plant/visitor）、候補正規名、採用正規名またはnull、典拠と外部ID、典拠の版/確認日、変更理由、確認者、判断状態、影響する原行番号。

候補と承認済みを分け、`_sp`・複合名を特定種へ自動分解しない。Aglais/Inachisなどを統合する場合も全行は保持し、変化するラベル数・ペア数を新しいtaxonomy版として管理する。原ラベル版の件数を、統合後の検証期待値にそのまま使わない。

## 6. 補助データとの結合

今回の対象CSVには花数も採種量もない。初回の取り込みでは他のCSVを自動結合しない。

将来 `AllData_PlotLevel_BothYears.csv` を使う場合、Yearの1/2に対する暦年対応を明示する。本監査では1→2014・2→2015で48区画年のVisitsが一致した。結合はYear×Plotを一意キーとして確認し、処理区も照合する。年単位集計をRound単位へ複製して、各回の実測花数と扱わない。

`TreatmentYearData.txt` も年コードを使い、行名が区画を兼ねる。`Raw_FlowerMatrix_BothYears.csv` は著者READMEで年ごとの区画順を説明しているため、行順だけで暗黙に結合しない。必要な補助資料は個別に版・ハッシュ・スキーマ・利用条件を確認する。

## 7. 工程4の受け入れ条件

1. 取得元・版・CC BY 4.0・帰属を追跡でき、原本サイズ・SHA-256・配布元MD5が一致する。
2. 元の3,882行と処理後3,882イベントが1対1で対応し、record_idの重複がない。
3. 全7列の値を原行からたどれ、7列同値行708グループも削除されず、1,930行を失わない。
4. 年別1,687/2,195、年×区画、年×Round、年×区画×Roundの全件数が監査表と一致する。
5. 原ラベル版で植物20・昆虫104ラベル・全体257ペアが維持される。ただし「種数」と表示しない。
6. 2014/2015のRound集合を維持し、15組の行なしを確認済み0件へ変換しない。
7. 変換は決定的。schema版、変換仕様版、コードのコミット、入力・出力ハッシュを記録し、同じ入力と版で同じ正規化結果を生成する。
8. アプリへ接続する際も、出典・英国実験・未同定の制約を表示し、計算機能は工程5・6の準備が整うまで有効にしない。

## 8. 再現性の来歴

取得日時と、決定的なイベント本体を別ファイルに分ける。出力JSONのUTF-8、改行、キー順、配列順、数値表現を定義し、時刻のように実行ごとに変わる情報をイベント本体へ混ぜない。出力ハッシュを出力ファイル自身へ埋めず、provenanceから参照する。

乱数シード・PRNG・反復仕様・計算コード版は工程5以降の計算来歴に加える。今回の監査と取り込み設計に乱数を使わない。
