# 実行状態と競合の仕様

正式RunResultのstatusは変更しない。以下はUIの状態。

| 状態 | 画面 | 次の操作/遷移 |
| --- | --- | --- |
| idle | 未実行。数値・図・保存リンクなし | 有効な入力でstart→loading |
| loading | 実データと来歴の読込。旧結果を消去 | 読込成功→running、失敗→error、取消→cancelled |
| running | 実計算と完了検証。推定の進捗率なし | 検証成功→successまたはempty_scope、失敗→error、取消→cancelled |
| success | 実行時条件と実結果。0%も含む | 試行取得、保存準備、編集、再実行 |
| empty_scope | 選択範囲に元記録なし。0の実測図を作らない | 条件変更/再実行、正式empty_scopeの保存 |
| error | 原因と条件画面への経路。値/図/保存なし | 入力や環境を確認して再実行 |
| cancelled | 中止。結果を採用しない | 条件を確認して再実行 |

## 要求IDとWorker寿命

startは前Workerをterminateし、旧Blob URLをすべてrevokeして新規run_id/Workerを作る。onmessage/onerror/onmessageerrorのクロージャーはWorkerオブジェクトの同一性とrun_idを確認する。cancelはterminateしrun_idを進め、payload/出力を消す。解除前に捕捉された旧コールバックもIDが違えば採用しない。失敗も同じ解放を行う。

各Workerは1実行のみ。全試行はそのWorker内に保持し、Providerがアンマウントされればdisposeする。ページ間移動ではProviderを保持する。タブ再読み込みで全結果が失われることをフォーム・状態画面・結果画面で説明する。永続保存・外部送信は行わない。

## 入力と結果を混ぜない

下書きは編集可能な文字列等、実行入力は既存コアで正規化した値。選択の並びが違っても正規化キーは同じになる。readyのモード・R・割合・シード・正規選択を実行要求へ照合する。

loading/runningまたは出力準備中の編集は処理を取消し、新条件を旧実行へ混ぜない。成功後の編集は実行時条件/結果を保持し「以前の条件」と明示する。再実行ボタンは保存された入力を下書きへ復元し、同じ条件で新規要求を開始する。現在の編集値であるかのように旧結果を表示しない。

## 試行切り替え

trial操作ごとにoperation_idを進め、最新要求に一致する返答のみを採用する。取得待ち中は、実際に表示している旧試行番号を明記する。返答のtrial_indexも要求番号へ照合する。全体summary/referenceは不変。trial取得エラーは成功扱いにせず実行をerrorへ移す。

## 出力の小状態

idle→preparing→readyまたはerror。計算のsuccess/empty_scopeと出力準備の成功は別。保存要求ごとにoperation_idがあり、古い返答は採用しない。準備中の多重実行を拒否する。完全結果をWorker内で再検証し、Blob/サイズ/ハッシュ形式を確認する。3URLの一部作成に失敗したら既存URLを解放し出力errorとする。出力失敗だけなら有効な計算結果を残して再準備できる。

取消はWorker内結果も破棄し、途中Blobを後からreadyにしない。次実行/取消/disposeで全URLを解放する。保存リンクはブラウザへダウンロードを要求するもので、OSの保存完了をアプリが保証したという通知は出さない。

## 失敗を隠さない

データ版/ハッシュ/来歴不一致、Web Worker/Web Crypto非対応、ネットワーク読込失敗、メモリ不足、入力不正、結果不整合をerrorにする。未コミットのアプリだけが異なる場合は開発用計算として明示し、正式保存を無効にする。計算来歴が失敗した場合は代用版や偽のコミットを使用しない。

ライブ通知はbusy領域の外にも置き、読み込み/計算/完了/失敗/取消を文字で通知する。実際の読み上げ機器による評価は今後必要。テストはclient.test・ExecutionFlow.testと実ブラウザの検証記録を参照。
