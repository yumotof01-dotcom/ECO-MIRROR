# 第10工程への引き継ぎ

第9工程の機能統合は既存の第8工程を継承したPR #8で提案する。一般公開、既存PRのマージ、mainへの直接pushは行わない。開始時と終了時に最新の継承/CI/未コミット状態を確認する。

## 優先する検証

1. 既存の独立Python監査を基に、選択スコープ・R・0/50/100%の結果を独立した方法で照合する。PCG/丸め/Fraction/type 7/全試行保存を変更しない。UI表示と保存の丸めが混じっていないか回帰する。
2. 実機Safari/iPad/Android等の低メモリでR100/1000・巨大保存・中断・連続実行を計測する。ピークRSS/ArrayBuffer/Blob/Worker寿命、タブ強制終了、ダウンロード後の解放を観測する。回数の黙った縮小をしない。
3. mainスレッドの結果到着時タスク（およそ50〜90ms）とSVG/option描画をプロフィールし、数学・正式結果・座標を保持する最小限の改善を検討する。表示用フラグメントを正式RunResultと偽らない。
4. キーボードのみで条件設定→実行→試行変更→ノード/リンク→統計表→保存→再実行を通して確認する。実際のスクリーンリーダーとOS文字拡大・タッチを評価する。axe検出0をWCAG全体の適合とみなさない。
5. 科学的な第三者レビューを受け、未確認/不在、訪花/受粉、記録/個体、原ラベル/種、分位範囲/信頼区間、英国/日本、処理/因果効果を読み違えないか確認する。

## 守る境界

- `src/features/data/`・`data/`・規範9文書・計算コアと既存依存の変更は不要だった。来歴の照合を弱めない。
- 同期の既存計算は専用Workerの中で実行する。全結果を保持し、UIはsummaryと現在の1試行。取消でWorkerを終了し、旧要求/旧操作は採用しない。
- データ/仕様/計算版とアプリ版を区別する。未コミットを実在コミットへ偽装せず、実装コミット→検証/来歴を次コミットの順を守る。
- `run-result.json`は同一バイトの正規契約、時刻/実行環境/アプリハッシュ/本体SHAは別来歴。表示の丸めは本体に保存しない。
- ブラウザへの保存結果インポート、ローカル永続化、共有サーバー、公開/デプロイは追加していない。必要なら次の依頼と明確な検証契約を待つ。
