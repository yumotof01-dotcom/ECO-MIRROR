## メインスレッドの応答

50ms間隔のタイマーとPerformanceObserverのlongtaskをQA側から観測した。R1000の計算中の最大タイマー間隔は136.9ms / 144.7ms、最長mainタスクは79ms / 81ms。計算11〜12秒全体のブロックは見られなかった。一方、結果到着時のSVG/React描画には短いタスクが残り、完全な無停止や常時60fpsを意味しない。

R1000の出力準備中の最大タイマー間隔は57.2ms / 75.9msで、longtaskの観測は0件。約2.7〜2.7秒のJSON構築とハッシュはWorker内で行われる。取消は実Worker.terminateで確認し、旧結果・保存リンクを復活させない。APIの進捗段階以外に架空の進捗率は作らない。

CDP Runtime.getHeapUsageの点観測。backing storageとJSヒープは別の分類で、これらの和をブラウザ全体のRSSと呼ばない。GC/Blob/ArrayBuffer/QA注入による変動がある。特にaxe実行後のmainヒープは監査コード自体を含み、純粋なアプリ比較に使わない。ピーク、プロセス全体、OS回収後の値、モバイルの上限は未測定。

Workerは次実行/取消/破棄でterminateし、全Blob URLをrevokeする。実ブラウザで取消時active Worker=0、連続実行時=1を確認。単体テストはURL解放と部分失敗時の解放も検証する。この寿命検証だけで低メモリ端末のOOMや長期的メモリリークがないと断定しない。

## 制約と対処

- Web Crypto.digestは86MB級Blobの全ArrayBufferを必要とする。全結果も保持するため低メモリでR1000の成功は保証しない。UIには負荷と取消/再実行の方法を表示し、回数を黙って減らさない。
- Workerの読み込み/転送/計算/出力例外はerrorとして表示する。ブラウザ/OSがタブ全体を強制終了した場合はページ内で回復通知を保証できない。
- 完了試行ごとの進捗APIは元コアにない。数式・実行順・保存契約を変えず、loading/running/検証/JSON構築/ハッシュの段階表示を採用した。
- iPad Safari、タッチ、低メモリ実機、CPUスロットル下の継続操作、Workerクラッシュの実OS再現は第10工程以降の検証対象。
- 初回データassetは約2.61MB（生成JS）、main JS約339KB（gzip約107KB）、Worker約54KB。追加のグラフ/統計/PRNG依存は導入していない。

## 再測定

完全履歴・実装コミット一致で`npm run build`。PlaywrightとChromiumを別のQA環境へ用意し、次を実行する。プロジェクトのpackage/lockは変えない。

```bash
ECO_MIRROR_BROWSER_PATH=/path/to/chromium node scripts/application/e2e.mjs
```

Playwrightは通常のNode解決先、または`CODEX_PRIMARY_RUNTIME_NODE_MODULES`配下から読む。任意の`ECO_MIRROR_AXE_PATH`はaxe.min.jsへのパス。実行ごとにQA記録を上書きし、取得した実装版・条件・環境を確認してから保存する。Linuxでは日本語フォントをQA環境側へ用意する。本アプリに外部フォント取得は追加していない。
