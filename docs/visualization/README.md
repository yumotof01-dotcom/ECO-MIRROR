工程7の実装・218テスト・GitHub CI成功と[PR #6](https://github.com/yumotof01-dotcom/ECO-MIRROR/pull/6)を確認し、先端`85c83737de6bc657bda877d176268bc43448a565`から独立ブランチ`feat/phase-8-network-visualization`を作成した。baseは`feat/phase-7-repeated-simulation`。工程9の本番状態管理や実行フローは含めない。

## 入出力と責務

| 場所 | 責務 |
| --- | --- |
| `src/features/visualization/adapter.ts` | 既存RunResultとtrial_indexを検査し、原ラベル・基準/抽出重み・相手数を表示データへ写す |
| `layout.ts` | 基準原ラベルIDの安定順だけから共通論理座標を作る |
| `NetworkComparison.tsx` | 左右比較、試行選択の通知、SVG、凡例、検索、線の表示絞り込み、詳細、キーボード操作 |
| `network.css` | 既存の緑/オフホワイト/ネイビーに合わせた名前空間付き表示スタイル |
| `src/dev/network-preview.tsx`, `dev/network.html` | 工程7の計算済み実データチェックポイントを読む独立プレビュー |

公開入口は`NetworkComparison({result, trialIndex, onTrialChange})`。`result`は既存`RunResult`、番号は存在する試行のみ。変更通知を親へ渡すcontrolled設計で、コンポーネントは試行を実行しない。結果はimmutableに扱い、変更時は別オブジェクトを渡す。アダプターは原データローダー、PRNG、抽出、統計の実行関数を一切importしない。

不明なスキーマ・未成功の結果・範囲外の試行・ノード/ペアの重複や順序違反・新規ペア・増加/負の重み・件数/相手数の不整合をエラー表示し、黙って修正しない。全結果の暗号学的な認証器ではなく、計算済み結果の可視化境界である。出典・実装リビジョン・正規JSONの完全照合は計算層の検証CLIが担当する。

## 描画技術と座標

Reactによる宣言的SVGを採用した。D3.jsとSVGを候補として比較したが、今回必要な安定二列配置・曲線・共通スケールは小さい純粋関数で明示できる。force simulationやD3のDOM操作を必要とせず、依存追加と工程4/6の再現用入力変更を避けられるため、追加ライブラリを使わない。数理モデルは変更しない。

論理幅820、植物x=270、昆虫x=530。ASCIIのID順に並べ、両側を基準の最大原ラベル数に合わせて上端54から下端へ等間隔に配置する。密な側の行間は30、疎な側はそれ以上。1ノードだけなら中央に配置する。高さは最大ノード数と行間だけから定める。原ラベルはIDの仕様固定の`plant:`/`visitor:`接頭辞だけを外し、その後の文字列を一切修正しない。

同一のlayout mapを両SVGに渡し、同じresult.referenceの試行切替時はmapを再利用する。検索・線フィルター・拡大・画面サイズを座標関数に渡さない。viewBoxを維持したままCSS上のSVG幅/高さだけを拡大する。表示幅が足りなければ左右共通のスクロール領域でパンし、狭い画面で論理座標を組み替えない。ランダム性・アニメーションはない。

## 比較規則・凡例

- 植物は左の緑、昆虫は右の黄褐色。左右両図に基準P₀とV₀の全原ラベルを同じ位置で残す。
- 各基準ペアに対し1本の線。複数記録を複数リンクに分割せず、w(D)とw(S)を別の整数重みで保持する。キーはIDの2要素組をJSON化し、区切り文字を推測解析しない。
- Aの実線は基準の観測関係、Bの実線は抽出で再確認された関係。Bの重み0は細い破線、相手数0のノードは白抜き/点線の輪郭と薄いラベル。消滅や不在とは呼ばない。
- 正の線幅は`1 + 5 × sqrt(count / max_reference_count)`、0の破線は1。両図で同じ基準最大値を使い、同じ記録件数を同じ太さにする。平方根は表示だけのスケールで、保存値・指標へ戻さない。
- 凡例に色、実線、破線、白抜き、太さの意味を記す。全対象の観測ペア数/抽出ペア数/未確認数と記録件数は計算結果からそのまま表示する。

## 操作とアクセシビリティ

原ラベルの検索はハイライトと選択候補を絞るだけで、図のペアを隠さない。任意に選択ノードの接続線だけを表示できるが、原ノードと座標は維持する。「図の表示対象」と「全対象の計算指標」を別々に明示する。リセットで全257ペアへ戻せる。

SVGのノード/リンクはクリック、Enter、Spaceで選択可能。各図に1つのTab入口を置き、矢印キーで植物→昆虫→リンクの安定順、Home/Endで先頭/末尾へ移動する。各図は別のtab-stopを持ち、選択とキーボードフォーカスを分ける。フォーカスと選択には輪郭/背景を表示する。ノード/全リンクのnative selectからも同じHTMLの詳細欄を開ける。詳細には原ID、原ラベル、両側の相手数や記録数、今回の確認状態を示し、aria-liveで更新する。

SVGのtitle/desc、フォームラベル、凡例、破線/白抜きによる色以外の区別、強制カラー設定を用意する。各図の原ラベルは省略しない。狭い画面では操作欄と詳細を縦配置にし、図は共通スクロールで全域へアクセスできる。読み上げ実機・タッチ実機の検証状況は[検証記録](validation.md)に区別して記載する。

## 開発者用プレビュー

```bash
npm ci
npm run dev -- --host 127.0.0.1
# http://127.0.0.1:5173/dev/network.html を開く
```

通常の`npm run build`は既存アプリだけを出力する。このプレビューはVite開発時の独立HTMLで、通常ページのルートやimportグラフに追加しない。保存済みの実データ50%（R=3のt=0,1,2）、100%、0%、empty_scopeを切り替える。合成fixtureは読み込まない。任意の既存R=100/1,000の結果も同じコンポーネントで受け取れるが、プレビューは新しい計算を実行しない。

出典はMoss & Evans (2022)、大学DOI 10.25405/data.ncl.17430548.v1、CC BY 4.0。原ラベルを保持した抽出/集計/描画であることを示す。全観測は完全な真値でなく、訪花は受粉成功でなく、線の重みは送粉効率でない。英国実験から日本の草原を断定しない。

## 工程9への引き継ぎ

既存の下書きUIと計算入口を接続する実行状態を設計し、成功時だけRunResultをこのコンポーネントへ渡す。idle/running/error/empty_scope/成功した0%を区別する。0%を許すUI仕様への整合、試行番号のcontrolled state、Worker/大きい結果の保持方法、来歴付き出力は工程9以降で行う。第8工程は既存の実行・書き出しボタンを有効化せず、結果画面を変更しない。
