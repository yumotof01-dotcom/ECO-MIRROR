# Codexへの引き継ぎ

## 作業場所

- 既存リポジトリ：<https://github.com/yumotof01-dotcom/ECO-MIRROR>
- 基盤ブランチ：`feat/foundation-phase-1-2`
- 新しいGitHubリポジトリは作成しない。mainへの直接変更・マージ・公開は行わない。
- 基盤PRが未マージなら、まずその差分とブランチを確認して引き継ぐ。mainしか取得しないと基盤コードが見えない。

## 今あるもの

React、TypeScript、Vite、Tailwind CSS、4画面と404、フォーム下書きの状態、初期値へのリセット、入力検証、科学的注意事項、DOMテスト、ビルド設定、CI、各種docs。

実データ、データローダー、PRNG、サンプリング、分析エンジン、実行状態、結果データ、グラフ、書き出し、サーバー、公開設定はまだない。実行・書き出しの無効状態は意図的であり、単にボタンを有効にして解消するバグではない。

## 次に行うこと：工程3

1. `AGENTS.md`、README、仕様、科学的注意事項、データ方針を読む。
2. `git status`、ブランチ、既存PR、現在のファイルを確認する。
3. 植物と昆虫の訪花記録を含む公開データ候補を調べる。Web of Lifeは候補のひとつであり採用済みではない。
4. `docs/data-policy.md` の各項目を実データの説明と元論文・利用条件で確認する。
5. 候補比較、未確認点、採用可否、可能な観測モデルの範囲をdocsに記録する。
6. 工程3の結果を作業ブランチとPRにまとめる。データ取得と正規化は工程4、数理仕様は工程5、計算実装は工程6以降。

## 次のCodexに渡す依頼文

> 既存の yumotof01-dotcom/ECO-MIRROR を使い、工程3「公開データの調査・選定」を進めてください。新しいリポジトリを作らず、最初にAGENTS.md、README、docs、現在のコード・ブランチ・PRを確認してください。基盤PRが未マージの場合はその変更を確認してください。植物と昆虫の訪花データについて、出典・対象分類群・観測方法・記録単位・0と欠測・利用条件・再配布条件を調べ、候補比較と採用理由、未確認事項をdocsへ記録してください。今回はデータの組込みや計算を実装せず、架空の結果も表示せず、作業ブランチとPRで提案してください。

## 実装を再開する際の確認

```bash
npm ci
npm run check
```

画面変更時は4画面、条件下書きの保持、リセット、不正な整数入力、未実行表示、404からの復帰を確認する。将来実データと計算を接続するときは、現在の「常に未実行」のテストを、状態遷移と来歴を検証するテストへ更新する。未実行と有効なゼロ結果を区別する原則は維持する。
