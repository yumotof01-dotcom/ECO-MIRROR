## 検証方法

scripts/usability/review.mjs は実データ・実Workerの反復2回結果を保持して4画面を巡回する。320×568、390×844、768×1024、1024×768、1440×900、1920×1080、CSS文字200%/400%を検査。axe-coreはQA用の別インストールを使いアプリへ同梱しない。日本語フォントもQA環境のみに設定した。

```sh
npm run check
# Playwright / Chromium / axe-coreを別途用意し、パスを指定する
ECO_MIRROR_BROWSER_PATH=/path/to/chromium ECO_AXE_PATH=/path/to/axe.min.js node scripts/usability/review.mjs
```

responsive-report.jsonが実測結果。自動検査はWCAG全体への適合証明ではない。CSSルート文字の拡大はOSの拡大やSafari実機の検証ではない。ネットワーク図・統計表内部のスクロールは許容し、ページ全体の横はみ出しを検査する。

## 実機・利用者テストシート

公開前にiPad第9世代/SafariとBluetoothキーボードで確認し、OS・ブラウザ版と日付を記入する。

1. 縦/横で全24区画と年別Roundを選べる。数値キーボードでシード42と回数100を入力。
2. 既定100回を実行、進捗が実試行数と対応し、タッチスクロールが継続できる。
3. 試行0→1→99、原ラベル検索、ノード・リンク詳細、SVG内スクロールを確認。
4. JSON/来歴/CSVをFilesへ保存し、PC上でSHA-256と行数を照合。
5. 0%、100%、記録のない条件、入力空欄、計算キャンセルから再実行。
6. キーボードのTab/EnterとVoiceOverで入力ラベル、状態通知、詳細、保存リンクを読む。
7. 文字拡大、画面回転、背景アプリ切替から復帰。1000回は100回成功後に行い、タブ再読込や保存失敗を記録する。
8. 初見参加者に「保持率は何か」「破線は絶滅か」「割合は調査時間か」を自分の言葉で説明してもらう。回答や所要時間は実際に観察したものだけ記録。

WebKitはこの環境の共有ライブラリ不足で起動できずBLOCKED。iPad/タッチ実機、VoiceOver、低メモリ・長時間利用はNOT TESTED。これらを理由に一般公開GOは出さない。
