# ECO MIRROR 仕様書

**現行は第9工程の公開前統合版。以下の工程1〜6の記述は各工程時点の履歴で、現在のUIを制限する規定ではありません。** 現行の画面・状態・出力は末尾の第9工程と[統合仕様](application/README.md)を参照してください。数理上の正本は引き続き`docs/simulation/`の1.0.0です。

## 1. 目的

植物と昆虫の公開訪花データを使って、観測条件による関係の見え方の違いを再現するWebシミュレーターを開発する。観測不足によって、生態系の状態を誤って判断するリスクを減らすことを目指す。この目的の達成は現時点で検証していない。

生成AIによる予測、未知の相互作用の補完、生態系の健康度・絶滅リスクの自動判定は行わない。

## 2. 画面基盤の範囲（工程1・2）

工程1は「要件・科学的前提の整理」、工程2は「開発環境・画面基盤」と定義する。完成版の機能と、今回動くものを分ける。

| 項目                                     | 工程1・2での状態                       |
| ---------------------------------------- | -------------------------------------- |

| 条件の保持                               | アプリ内メモリのみ。再読み込みで消える |

## 3. 画面仕様

### ホーム `/`

目的、今後の使い方、現在の実装範囲を説明する。「観測条件を見てみる」は `/simulation`、「研究の背景を読む」は `/research` に移動する。植物と昆虫のSVGは説明用とし、実データではないことを図のそばに明記する。

### シミュレーション `/simulation`

公開データが未接続であることを表示する。入力値は実験条件の下書きであり、分析結果ではない。

| 入力         | UI初期値 | 入力範囲               | 注意                                                   |
| ------------ | -------- | ---------------------- | ------------------------------------------------------ |
| データセット | 未接続   | 選択不可               | 候補を採用済みと表示しない                             |
| 観測割合     | 50%      | 1〜100、1刻み          | 抽出割合の案。現場の観測時間・検出確率とは同一視しない |
| 反復回数     | 100      | 1〜1,000の整数         | 科学的な推奨値ではない                                 |
| 乱数シード   | 42       | 0〜4,294,967,295の整数 | PRNGの採用・実装は後工程                               |

反復回数・シードの空欄、小数、範囲外をエラー表示し、`aria-invalid` と説明文を結び付ける。実行ボタンは入力値に関係なく無効。初期値へのリセットは動作する。入力値から計算や通信を開始しない。抽出単位・丸め規則・モデル・範囲は工程5で確定し、必要に応じてこのUIも改訂する。

### 分析結果 `/results`

直接アクセスでも「未実行」「公開データ未接続・計算未実装」を示す。未実行を値0の結果に変換しない。今後の比較観点は文章のみで案内し、グラフの見本・架空の指標・偽の成功通知は置かない。結果を書き出すボタンは無効。

### 研究情報 `/research`

目的、科学的な注意事項、背景論文、データベース候補と未採用の状態を示す。各資料は出典へのリンクを持つ。Web of Lifeへのリンクは個別データの採用・再配布許諾を意味しない。

### 共通部分

ナビゲーションに現在地を表示。画面遷移時はタイトルを更新し本文へフォーカスする。本文へのスキップリンク、フォームのラベル、無効ボタンの理由、404からの復帰経路を用意する。狭い画面では縦並びにする。

## 4. 非機能要件

- TypeScriptのstrict設定を使う。
- 依存をロックし、`npm ci` で同じ依存構成を取得できるようにする。
- UI・データ・計算を分離する。現時点でデータ取得・計算の仮実装は置かない。
- 外部フォント・画像配信・AI APIへの依存を作らない。図はリポジトリ内のSVGで描く。
- キーボード操作、フォームの説明、色以外の状態表示、動きを抑える設定に配慮する。実ブラウザによる適合確認は別途必要。
- 将来の計算結果にはデータID・ハッシュ・条件・シード・PRNGと計算手法の版を結び付ける。

## 7. 第4工程のデータ処理基盤

大学保管v1の原CSVと取得時の公式メタデータを同梱し、固定サイズ・SHA-256・MD5、CC BY 4.0、全3,882行の正規化と第3工程の全監査値との照合、原行追跡、決定的生成とコード来歴、型安全なローダーを実装した。仕様と受け入れ条件は [implementation.md](data/cc-plant-pollinator/implementation.md)、検証は [phase4-validation.md](data/cc-plant-pollinator/phase4-validation.md)。

既存画面には接続しない。工程1・2の画面仕様と未実行・実行無効の状態を維持する。全記録は英国実験の訪花行であり、分類名を修正せず、同値行を削除せず、行のない15組を実施済み0としない。実施日時・実績努力量・ブロックを推測しない。指標と観測モデルの定義は工程5、計算実装は工程6以降。

## 8. 第5工程の数理仕様

正本は [docs/simulation/](simulation/README.md)。選択した年・区画・処理・年別Roundの全原記録を基準とし、各イベントを非復元・固定件数で抽出する。整数p=0〜100に対し `k=floor((N*p+50)/100)`。PCG-XSH-RR 64/32、棄却法、前方部分Fisher–Yates、元番号順の保存を規定した。

指標は記録数、植物/昆虫の原ラベル数、観測ペア数、見えなくなったペア数、ペア保持率、各ラベルの観測相手数、参照ノードを分母に固定した二値Connectance。分母0はnull、正の参照に対する0件抽出は有効な0。反復の系列、平均・標本SD・type 7分位点と正確な保存形式も文書化した。

これは数理設計の確定であり、PRNG・抽出・指標・反復・描画の実装はない。0〜100%は将来の入力仕様で、現在の未接続フォームは1〜100%のまま。工程6は単一コアだけを実装し、反復は工程7、画面接続は工程8・9とする。科学的な未確認事項と用途の制約は [限界](simulation/scientific-limitations.md) を参照。

## 9. 第6工程の単一試行コア

工程5の数理仕様1.0.0に従い、条件正規化・原順の範囲選択・半数切上げ・BigIntのPCG32/棄却法・部分Fisher–Yates・原ラベルの固定基準ネットワーク・Fraction・正式な単一結果と別来歴を実装した。[実装仕様](simulation/phase6-implementation.md)と[検証記録](simulation/phase6-validation.md)を参照。

正式入口は全件ローダーを使用し、全3,882行の条件と原番号を再検査し、イベント/辞書のハッシュも照合する。公開結果はsingle_trial、t=0、R=1。正の参照の0%は成功、N=0はempty_scopeとして比較を生成しない。計算は画面から独立し、元データ・正規化・ローダー・数理仕様を変更しない。

既存画面の未接続・未実行・実行無効を維持する。反復、図、画面結果、ユーザー向け出力、AI、バックエンド、公開は追加していない。工程7で反復と集計を実装する。

工程7で1〜1,000回の反復と7指標の厳密な統計、工程8で固定共通座標の比較SVGを実装した。正式RunResult、全試行保存、Fraction/SqrtFraction、PCG32、原分類ラベルを維持する。

## 11. 第9工程の現行操作仕様

`/`から「シミュレーションを始める」で`/simulation`へ移動する。初期条件は両年、全24区画、全4処理、年別の全元Round、50%、seed 42、反復100回。すべて明示値で渡す。年内Roundは元ラベルを使い、異なる選択項目はAND・同項目内はOR。空選択は入力エラー、妥当な条件のN=0は実行後empty_scope。

割合は0〜100の整数。シード・Rは編集途中も文字列で保持し、空欄・符号・空白・指数・小数・範囲外を拒否。シード0〜4294967295、R=1〜1000。単一と反復R=1を区別し、後者の標本分散/SDはnull。

実行要求ごとに新規Workerと要求IDを割り当てる。loading/running/success/empty_scope/error/cancelled/idleはUIの状態。取消はWorkerを破棄し、正式結果statusへ追加しない。全結果をWorkerに保持し、画面へはヘッダー、サマリー、分布用スカラー、現在の1試行を渡す。結果は実行時点の入力と結合する。実行中の条件変更は取消、成功後の変更は以前の条件と明示する。

`/results`は成功時のみ実数値と図を表示する。単一試行と反復全体の統計を分ける。試行変更は保存済みの1試行を取り出し、再計算しない。正式契約を満たした結果だけをWorker内で検証し、正規JSON・別来歴・Fractionの分子分母を含むCSVへ保存する。未コミットアプリは開発用と表示し正式保存不可。来歴の詳細は[出力仕様](application/exports.md)。

`/research`にはMoss & Evans (2022)、大学保管v1 DOI、CC BY 4.0、加工内容、英国の訪花記録という範囲、元著者の推奨を意味しないことを記す。バックエンド・外部送信・AI・公開・再読込後の永続保存は追加しない。アクセシビリティと実測上の限界は[検証記録](application/validation.md)。
