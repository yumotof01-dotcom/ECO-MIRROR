# 乱数・シード・抽出順序の仕様 1.0.0

本書は固定する数学的仕様であり、PRNGや抽出の実行コードではない。モデル全体は[model-specification.md](model-specification.md)。実装は工程6。

## 1. 選定

| 候補 | 確認した性質・実装上の判断 |
| --- | --- |
| PCG-XSH-RR 64/32（PCG32） | **採用**。公式の初期化・範囲付き整数化・既知出力が公開され、64bit状態をTypeScriptのBigIntで正確に扱える |
| xoshiro128** | [著者の参照実装](https://prng.di.unimi.it/xoshiro128starstar.c)がある32bit演算の候補。4語の状態を持ち、単一32bitシードの展開規則も追加で固定する必要がある。MVPでは採用しない |
| Math.random() | 不採用。[ECMAScript仕様](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math.random)は生成方法を実装依存とし、このAPIに本仕様のシードを渡す契約がない |

PCG32を他方式より統計学的に普遍的に優れていると主張する判断ではない。参照値との照合、正確な整数演算、シードと系列の分離を優先した。BigIntの実行性能と複数エンジン間の一致は工程6・10で確認する。

規範の識別子は `prng_algorithm = "pcg-xsh-rr-64-32"`、`randomness_version = "1.0.0"`。単に「PCG」と記録して別の出力変換へ置き換えない。

参照：Melissa O'Neill, [公式C最小実装の説明・出力例](https://www.pcg-random.org/using-pcg-c-basic.html)、[pcg_basic.c（固定コミット）](https://github.com/imneme/pcg-c-basic/blob/bc39cd76ac3d541e618606bcc6e1e5ba5e5e6aa3/pcg_basic.c)、[demo（同コミット）](https://github.com/imneme/pcg-c-basic/blob/bc39cd76ac3d541e618606bcc6e1e5ba5e5e6aa3/pcg32-demo.c)。参照コードを取り込む際はそのライセンスも保持する。工程5では取り込まない。

調査時に固定コミットの原ファイルを読んで確認したSHA-256は、pcg_basic.cが `b6582a071a8a090a293621523c063d125a532d772a2a1eb7d60b3e695fe47746`、demoが `6458e24b2f0b63fdf12db5b62f03ee1df1292bdf38663b972f700e11346a30fb`。PCG本体を実行して独自の出力列を生成する検証は工程6に残す。

## 2. シードと試行番号

- `master_seed` は整数Number、0〜4,294,967,295（$2^{32}-1$）。小数、NaN、Infinity、文字列、範囲外は `INVALID_SEED`。暗黙の `>>>0` による切詰めはしない。
- `trial_index=t` は0始まり、0〜999。反復回数Rは1〜1,000で、通常0≤t<R。単一試行はt=0。
- この試行の初期シード組は $(\mathrm{initstate},\mathrm{initseq})=(s,54+t)$。sを64bitへゼロ拡張する。t=0,1,999の系列IDは54,55,1053。
- 32bitへハッシュして試行別seedを作らず、**同じmaster seedと異なる系列IDの組**を各試行へ渡す。単一の数値シードを毎回リセットして同じ標本を繰り返す実装をしない。
- 54は公式のs=42、initseq=54の参照ベクトルへ第1試行を対応させるための固定オフセットであり、生態学的意味はない。
- 時刻、処理時間、Math.random、暗黙のユーザー環境、ワーカー番号をシードに加えない。UIの既存文字列入力を将来変換する際は、数字のみの文字列を厳密検査して範囲内のNumberへ変換する。空欄・空白・指数表記・符号付き文字列はエラー。先頭0は数値として同じシードになると明記する。

## 3. 状態と初期化

$M_{64}=2^{64},M_{32}=2^{32},A=6364136223846793005$ とする。状態Xと固定増分Cは非負の64bit整数。

1. $q=54+t$、$X=0$、$C=(2q+1)\bmod M_{64}$ とする。
2. 次節の `nextUint32` を1回呼び、その出力を捨てる。
3. $X=(X+s)\bmod M_{64}$ とする。
4. `nextUint32` をもう1回呼び、その出力を捨てる。
5. 以後の出力が抽出に用いる系列。Cは試行中に変更しない。

s=42,t=0ではC=109、2回の初期化後のXは `1753877967969059832`（16進 `185706b82c2e03f8`）。初期化の2出力は `random_word_count` に含めない。

0件/全件を返す特例では初期化自体も行わない。シード組は結果に記録するが、`random_word_count=0` とする。

## 4. nextUint32の数式

呼出前の状態を $x=X$ とし、次の状態と出力を**旧状態xから**求める。

$$
X\leftarrow(Ax+C)\bmod 2^{64},
\quad z=\bigl(((x\mathbin{\gg}18)\oplus x)\mathbin{\gg}27\bigr)\bmod2^{32},
\quad r=x\mathbin{\gg}59.
$$

rは0〜31。出力uは32bitの右回転：

$$
u=\begin{cases}
z,&r=0,\\
(z\mathbin{\gg}r)\;\mathbin{\mathrm{OR}}\;((z\mathbin{\ll}(32-r))\bmod2^{32}),&1\le r\le31.
\end{cases}
$$

$0\le u<2^{32}$。演算記号は非負整数のビット演算。zを**回転前に**32bitへ制限すること、更新後のXをzの計算に使わないことが重要。

TypeScriptでは64bitの積・加算・シフト・マスクをBigIntで行う。定数も正確なBigIntとして与え、丸められたNumberの巨大な定数から変換しない。BigIntには `>>>` がないので、非負の値への `>>` を用いる。Numberの32bit演算だけで64bit状態を代用しない。最終uだけを0〜$2^{32}-1$の正確なNumberへ変換できる。符号付き負数の乱数語を返さない。

64bit状態をJSONに記録する場合は0埋め16桁の小文字16進文字列。BigIntをJSON.stringifyへ直接渡さない。

## 5. 偏りを避ける範囲付き整数

`boundedUint(m)` は整数 $1\le m\le2^{32}-1$ に対し0〜m−1を返す。このアプリで実際に渡すmは最大3,882。

1. m=1は0を返し、乱数を消費しない（本仕様の明示的な特例）。範囲外・不正型は `INVALID_BOUND`。
2. $h=2^{32}\bmod m$ とする。
3. 次のuを取得する。u<hなら捨て、同じmで次のuを取得する。
4. u≥hなら $u\bmod m$ を返す。捨てた語も消費数に含める。

採用範囲[h,2³²)の長さはmの倍数なので、理想的な一様語列に対する剰余偏りを除去できる。`u % m`だけ、`floor((u/2^32)*m)`、ランダムなsort比較関数へ置き換えない。

公式Cの `-bound % bound` はunsignedの桁あふれを利用するため、JavaScriptでその文字列をそのまま計算しない。本仕様は正の整数定数 `4294967296 % m` でhを定める。棄却回数に上限を設けて偏った値へfallbackしない。外部キャンセル等は実行の中断とし、成功した比較結果を返さない。

## 6. 抽出での消費規則

[前方部分Fisher–Yates](model-specification.md#5-抽出アルゴリズムの規範)のi番目の交換だけがm=N−iの範囲付き乱数を要求する。0<k<Nならmは常に2以上。範囲付き1回に複数のuが必要な場合がある。メトリクス、ソート、表示、ハッシュは乱数を消費しない。

`random_word_count` は初期化後に要求したuの総数。k=0又はk=Nなら0。0<k<Nならk以上。描画・途中の進捗更新・反復のスケジューリングでこの値や結果を変えない。

| --- | --- | --- |
| 1 | `a15c02b7` | 2707161783 |
| 2 | `7b47f409` | 2068313097 |
| 3 | `ba1d3330` | 3122475824 |
| 4 | `83d2f293` | 2211639955 |
| 5 | `bfa4784b` | 3215226955 |
| 6 | `cbed606e` | 3421331566 |

工程6ではこの完全一致、seed 0/maxの決定性と符号、リセット、入力不変性、棄却語を含む消費順をテストする。範囲付き乱数のテストでは供給語を明示したテストダブルも使う。例：m=3、供給[0,1]なら0を棄却し1を採用、出力1、消費2。m=10、供給[5,16]なら5を棄却し出力6、消費2。これらの供給語はPCG出力を装うものではない。

## 8. 再現と独立性の限界

異なる試行は異なる系列IDを使い、グローバルPRNG状態を共有しない。ただし有限で決定的なPRNGから、厳密な確率論的独立性や、試行で同じ標本が一度も出ないことを保証しない。同じ標本になった試行を削除・再抽出してはならない。

再現には入力の版・ハッシュ、選択範囲、原順、p・丸め、シード組、初期化・棄却・交換規則、各仕様と実装の版が全て必要。シードだけを保存して再現できると主張しない。[結果の来歴](reproducibility.md)も参照する。
